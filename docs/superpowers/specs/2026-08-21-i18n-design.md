# Interface i18n — zh-TW default, English fallback — design

**Date:** 2026-08-21
**Target version:** v1.5.0
**Status:** approved, ready for planning

## Goal

Translate the whole player interface. **zh-TW (Taiwan terminology) is the default**; the UI
falls back to English when the system language is not Traditional Chinese. A segmented
toggle in the top right switches language explicitly, and the choice is remembered.

## Constraints inherited from the project

These are not negotiable and every decision below is shaped by them:

- **No build step, no dependencies, no framework.** No i18n library, no npm, no bundler.
- **`file://` must keep working.** The new dictionary is therefore a *classic* script, like
  `lib/stems.js` — not an ES module.
- **Nothing leaves the machine.** No web font for CJK; system fonts only.
- **Stem filenames stay English.** `vocals.wav`, `guitar.wav`, … in every saved zip,
  regardless of UI language. Explicit user requirement, pinned by a test.
- **Every local asset URL carries a matching `?v=`.** This change adds a fifth versioned
  file, so the bump touches more places than before.

## Decisions

| Question | Decision |
|---|---|
| Where does the dictionary live? | New `lib/i18n.js`, a classic script — approach A below. |
| Are instrument lane labels translated? | **Yes.** Filenames written to disk are **not**. |
| Switcher control | Segmented two-button toggle, top right of `.bar`. |
| Is an explicit choice remembered? | **Yes**, `localStorage`, every access in `try/catch`. |
| Do README/docs get translated? | **No.** UI only. `docs/behaviour.md` gains an English section. |
| How does the UI update on switch? | In place, no reload — audio must not be disturbed. |
| Bare `zh` (no region) | → **zh-TW**, following "the default is zh-TW". |
| `zh-CN` / `zh-Hans` | → **English**. Taiwan terminology does not serve Simplified readers. |

## Approaches considered

**A. `lib/i18n.js` classic script + `data-i18n` attributes — chosen.**
One dictionary file, static copy annotated in `index.html`, dynamic strings via `t()`.
`separate.js` is an ES module but reads the classic script's global off `window`, so there
is exactly one dictionary. `lib/stems.js` is untouched.

**B. Dictionary inlined in `app.js` — rejected.**
No new versioned asset, but `app.js` is already 830 lines and organised by section banners;
~180 lines of string data would swamp it, and `separate.js` would still need the dictionary
hung off `window`. All of A's coupling, none of A's separation.

**C. Re-render everything from JS — rejected.**
Moving the dropzone prose, hints and button text into JS templates gives one rendering path,
but guts `index.html` as a readable document and pushes another ~120 lines into `app.js`.
Overkill for two locales.

## Architecture

### `lib/i18n.js` (new)

Classic script, loaded **first** in `index.html`, exposing:

```js
window.SansI18n = { t, apply, setLocale, getLocale, detectLocale, LOCALES, DICT }
```

- **`t(key, params)`** — `DICT[locale][key]`, falling back to `DICT.en[key]`, then to the key
  itself. Interpolates `{name}` placeholders by simple regex replace.
- **`apply(root = document)`** — walks three attribute forms:
  - `data-i18n="key"` → sets `textContent` (the safe default)
  - `data-i18n-html="key"` → sets `innerHTML`; **only ever our own dictionary strings**, used
    for the dropzone prose and the keyboard hint, which contain `<strong>` and `<code>`
  - `data-i18n-attr="title:lane.tip,aria-label:play.aria"` → sets attributes
- **`detectLocale(langs)`** — takes the language list as an argument (defaulting to
  `navigator.languages`) so the detection table can be unit-tested without stubbing
  `navigator`.
- **`setLocale(loc, { persist = true })`** — see "Switching" below.
- **No plural framework.** Exactly one string needs plural agreement in English
  (`Decoding 3 files…`); it is two keys and the caller picks. Chinese needs neither.

### Detection order

1. `localStorage['sans_bass.lang']`, if it names a known locale.
2. Otherwise scan `navigator.languages` (or `[navigator.language]`): the first tag matching
   Traditional Chinese — `zh-TW`, `zh-Hant*`, `zh-HK`, `zh-MO`, or bare `zh` — yields `zh-TW`.
3. Otherwise `en`. This deliberately includes `zh-CN` and `zh-Hans`.
4. No `navigator.language` at all → `zh-TW`, the stated default.

Every `localStorage` read and write is wrapped in `try/catch`. A throw must never propagate:
`app.js` wires all its listeners from one flat run of top-level statements, so an exception
during setup silently kills every listener below it — the exact failure mode of v1.4.0.

### Switching without disturbing audio

No `location.reload()`. A reload would discard decoded `AudioBuffer`s and stop playback in
the middle of a practice loop, which is the one thing the player exists to protect.

`setLocale(loc, { persist })` does, in order:

1. persist the choice, if `persist` (`try/catch`)
2. set `document.documentElement.lang`
3. set `document.title` from the dictionary
4. `apply(document)` — every static annotated node
5. dispatch `sansbass:langchange` on `window`

`app.js` listens and runs **`retranslate()`**, which re-renders exactly five stateful strings:

- the mode dropdown — rebuilt, with `el.mode.value` restored afterwards
- the lane names — the `.txt` span inside each lane is mutated **in place**
- the loop badge
- the all-toggle label
- the status line

`retranslate()` **must not rebuild the lanes**: that would drop the canvases and force a full
waveform re-render. It must not touch `tracks`, `sources`, gain nodes, or the playhead.

`separate.js` listens for the same event and re-renders its own last status.

**Initial load calls `setLocale(detectLocale(), { persist: false })`.** Only a click on
the switcher persists. Otherwise the first visit would freeze the auto-detected locale in
storage, and a user who later changed their system language would never see the change.

### The status line

`say()` currently takes an already-rendered string, so a visible message would freeze in the
old language across a switch. It becomes `say(key, params, isErr)` and stores
`{ key, params, isErr }` in a module-level `lastSay`, which `retranslate()` re-renders.
`separate.js`'s `status()` gets the same treatment.

Worker error text (`m.message`) stays raw — it is a technical detail — wrapped in a
localized prefix.

### The mode-select refactor

Today `el.mode`'s option *value* is the label string (`app.js:297`), and `setMode` compares
`t.label !== mode` (`app.js:669`). Translating labels forces this to a stable key. It also
fixes a latent bug: two unrecognised files whose filename-derived labels collide currently
produce two dropdown entries that cannot be told apart.

New option values: `'mix'`, the stem key (`vocals`, `guitar`, …), `lane:<i>` for an
unrecognised file — where `<i>` is that track's index in the sorted `tracks` array, the
same index the `1`–`6` keyboard shortcuts use — and `'custom'`. `setMode` maps key → track through a `laneKey(t, i)` helper.
The call sites at `app.js:645,654,671,679,681,689` already pass `'custom'`/`'mix'` and are
unaffected.

### `lib/stems.js` is not modified

It keeps its English `label` as the stable identity, so `tests/stems.test.js` needs no
changes. `app.js` gains:

```js
laneLabel(t) => t.stem ? tr('stem.' + t.stem) : t.label
```

A filename-derived label for an unrecognised file is not translatable anyway.

**Targeted fix on the same line:** `name.innerHTML = ...${t.label}...` (`app.js:315`)
interpolates a filename-derived string into markup unescaped. Since that line is being
rewritten for `laneLabel`, the label goes in via `textContent` on the `.txt` span.

### Switcher markup and styling

```html
<div class="lang-toggle" role="group" data-i18n-attr="aria-label:lang.aria">
  <button type="button" data-lang="zh-TW">中文</button>
  <button type="button" data-lang="en">EN</button>
</div>
```

Sits in a right-hand flex group alongside `.loadzone` inside `.bar`. Active half filled with
`--accent`, inactive transparent with a `--line` border. Wired through `on()`, never
`addEventListener` directly — per CLAUDE.md.

`styles.css` also adds `"PingFang TC", "Microsoft JhengHei", "Noto Sans TC"` to the body font
stack: Windows' `Segoe UI` has no CJK coverage. System fonts only — a web font would be an
outbound fetch.

## Testing

### `tests/i18n.test.js` (new, added to `tests/test.html`)

1. **Key parity** — both locales have identical key sets; no empty values.
2. **Placeholder parity** — the set of `{name}` tokens is identical per key across locales.
3. **`detectLocale` table** — `zh-TW`→`zh-TW`, `zh-Hant-TW`→`zh-TW`, `zh-HK`→`zh-TW`,
   `zh`→`zh-TW`, `en-US`→`en`, `zh-CN`→`en`, `ja`→`en`, `[]`→`zh-TW`.
   `detectLocale` therefore takes the language list as an argument so it can be tested.
4. **Stem filenames never localize** — with the locale set to `zh-TW`, `assignStems` output
   `.stem` values are still `vocals|guitar|bass|drums|piano|other`, and save-path zip entry
   names are `<song>/vocals.wav`. This pins the user's explicit constraint.
5. **No missing keys in markup** — fetch `index.html` over HTTP (the way `versions.test.js`
   does) and assert every key named by a `data-i18n*` attribute exists in both locales.

### Manual, recorded in `docs/behaviour.md`

The UI is out of unit-test reach, so these are observable-outcome checks:

- **Switch mid-playback** → `AudioContext.currentTime` keeps advancing, the playhead keeps
  moving, no audible glitch. *Observe the clock, not the parameters.*
- **Switch with a loop armed** → the badge text changes language; `loopStart`/`loopEnd` and
  the audible wrap point are unchanged.
- **Switch with an error status visible** → the message re-renders in the new language.
- **Switch after separation** → lane names change; a subsequent Save still writes
  `vocals.wav` etc.
- **Switcher visibility** → verify with `getComputedStyle(el).display`, not `el.hidden`,
  per the project's own `[hidden]` gotcha.

## Risks

- **`localStorage` on `file://`.** Chrome permits it, but a throw during `app.js` top-level
  setup would silently kill every listener below it. Every access is guarded.
- **Version drift.** Five files now carry `?v=` instead of three. `tests/versions.test.js`
  is the guard; `CLAUDE.md`'s gotcha text must be updated to match.
- **CJK layout.** Chinese strings change button widths — the header, the `.controls` row and
  the keyboard hint need a look at narrow widths.
- **`retranslate()` overreach.** Rebuilding lanes instead of mutating them in place would
  drop canvases and re-render every waveform. Called out in the code with a comment.
