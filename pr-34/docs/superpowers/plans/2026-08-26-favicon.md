# Favicon and iOS Home-Screen Icon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give sans_bass a tab favicon and an iPhone home-screen icon — six waveform bars in the app's stem colours with the bass lane flattened — plus a `theme-color` so Safari's chrome stops painting white above a near-black page.

**Architecture:** One hand-written `icons/icon.svg` is the source of truth. A one-off shell script rasterises it to two committed PNGs with `rsvg-convert`; nothing runs at serve or deploy time, so the project's no-build-step constraint holds. Four lines in `<head>` wire them up with relative paths so the per-PR preview prefix `/pr-<N>/` still resolves. The existing `?v=` cache-buster guard is widened to cover image assets, which is what makes the new URLs impossible to leave behind at the next version bump.

**Tech Stack:** Vanilla HTML/SVG, `rsvg-convert` (librsvg, local only), the existing browser test page `tests/test.html`.

**Spec:** [`docs/superpowers/specs/2026-08-26-favicon-design.md`](../specs/2026-08-26-favicon-design.md)

### Task 2: The PNG generator

**Files:**
- Create: `scripts/make-icons.sh`
- Create (generated, binary): `icons/favicon-32.png`, `icons/apple-touch-icon.png`

- [ ] **Step 1: Write the script**

Write `scripts/make-icons.sh`:

```bash
#!/usr/bin/env bash
# make-icons.sh — regenerate the PNG icons from icons/icon.svg
#
# This is NOT a build step. The PNGs it writes are committed to the repo; the script exists
# so a colour or geometry change in icon.svg can be re-rasterised without hand-editing a
# binary. Nothing in the site, the tests, or CI ever runs it.
#
# Needs librsvg:  brew install librsvg
#
# --background-color is load-bearing, not tidiness. rsvg-convert leaves the canvas
# transparent wherever the SVG does not paint, and iOS composites a transparent
# home-screen icon onto black — so the flag, not the <rect> inside the SVG, is what
# guarantees an opaque tile even if the artwork later gains a margin.

set -euo pipefail
cd "$(dirname "$0")/.."

command -v rsvg-convert >/dev/null || {
  echo "rsvg-convert not found — brew install librsvg" >&2
  exit 1
}

render() {   # render <size> <outfile>
  rsvg-convert --background-color='#0d0d10' -w "$1" -h "$1" icons/icon.svg -o "$2"
  echo "==> $2  (${1}x${1})"
}

render 32  icons/favicon-32.png
render 180 icons/apple-touch-icon.png
```

- [ ] **Step 2: Make it executable and check it matches the other scripts**

```bash
chmod +x scripts/make-icons.sh
ls -l scripts/
```

Expected: `make-icons.sh` shows `-rwxr-xr-x`, the same mode as `serve.sh`.

- [ ] **Step 3: Run it**

```bash
./scripts/make-icons.sh
```

Expected output, exactly two lines:

```
==> icons/favicon-32.png  (32x32)
==> icons/apple-touch-icon.png  (180x180)
```

- [ ] **Step 4: Verify the dimensions**


Expected: `pixelWidth: 32` / `pixelHeight: 32` for the first, `180` / `180` for the second.

- [ ] **Step 5: Look at the 180 and confirm it is the artwork, opaque**

Read `icons/apple-touch-icon.png`. Expected: the same six bars as Task 1 Step 3, on a solid

- [ ] **Step 6: Commit**

```markdown
**Design docs:**
- Favicon: [Spec](superpowers/specs/2026-08-26-favicon-design.md) [Plan](superpowers/plans/2026-08-26-favicon.md)

**What was built:**
- `icons/icon.svg` — six bars in the stem colours with the bass lane flattened to a grey

  stayed green.
- `[note]` iOS applies its own corner mask to a home-screen icon, so the artwork ships full
  bleed; pre-rounded corners render as a double radius.
```
